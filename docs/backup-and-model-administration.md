# 备份、恢复、存储接口与模型管理

管理入口：[邮箱账户](https://album.learnforeverything.com/account/)。使用 `ADMIN_EMAIL` 对应的已验证、已开通邮箱登录后，账号审核区下面会出现“数据备份与模型管理”。普通用户和未登录访客均不能调用这些接口。

## 下载完整数据备份

选择“下载完整备份 ZIP”。支持目录访问的电脑浏览器也可选择“备份到文件夹”，每次会新建一个带时间与随机后缀的目录，不覆盖已有备份。保持页面打开直至完成，再把 ZIP 或整个文件夹放到自己管理的安全位置。

包含以下完整业务数据：

| 数据 | 保留内容 |
| --- | --- |
| 用户与账号 | 用户 ID、邮箱、审批状态与记录、剩余额度、会员截止时间 |
| 照片 | 上传原图、AI 生成图的原始字节、归属、名称、类型、时间 |
| 相册 | 标题、样式、页序、说明文字、修订号、分享令牌与访问密码摘要 |
| 业务记录 | 创作任务、评论、点赞、评分、订单、模型参数、管理日志 |

**不包含**验证码、登录会话、分享临时会话、限流和维护锁、服务器密钥。这些不是可迁移的长期业务内容。登录会话不会在导出时失效；恢复到新服务器后用户重新邮箱登录。站点源码与依赖锁文件保存在 GitHub，服务器密钥、DNS、邮件域名和部署配置须另外安全保管及重新配置。备份里的模型参数不是 API 密钥。

格式为 `manifest.json` + `records.json` + `files/<序号>.bin`。清单记录格式版本、全部表的数量及 SHA-256 摘要，每张照片独立校验。照片使用原始字节，未重新压缩；分享设置保持原样。备份含私人资料，不能提交到公开 GitHub 或放进公开网页目录。

导出过程中短暂暂停数据库写入，包括上传、生成、审核和可能结算订单的请求；已分享相册仍可浏览。正在生成的任务或其他写入未结束时拒绝开始备份，不会取消任务。浏览器每 30 秒续期维护锁；关闭或断网后最多约 10 分钟自动放开写入，下次操作清理过期暂存文件。过期快照不能继续下载，需重新开始。

ZIP 下载／导入上限 256 MiB（生成前还预留清单空间）；更大的照片集合请用文件夹方式逐张处理，单图最大 25 MiB。网页版数据记录及清单合计上限 16 MiB、业务记录最多 10 万条。超过时明确报错，绝不静默截断。数据达到此规模前，应安排数据库原生导出或扩展分片备份流程；目录模式只解决照片体积，不绕过记录上限。

## 校验及在线补回

1. 在“校验与恢复”选择 ZIP 或备份文件夹。
2. 浏览器检查全部照片及记录摘要；服务器比较当前记录，并检查已存在照片的内容。
3. 预览列出待补回、相同记录和冲突。**预览不修改业务数据。**
4. 只有无冲突且存在缺失内容时，输入“仅恢复缺失数据”执行补回。

已有相同记录跳过；已有但不同的账号、额度、相册修订等会阻止整个恢复。邮箱或交易编号已属于其他记录也会阻止。恢复不会将现有额度回滚到旧值，不会重置审批，不会覆盖用户新作品。单次最多补回 500 条业务记录；超限请使用空白目标的离线恢复。

新照片先按独立对象键暂存，校验全部通过后在一个事务中写入所有缺失记录与完成日志。插入失败则整个数据库事务回滚；取消只清理这次未被业务记录引用的暂存文件。已完成提交不能被并发取消清掉。文件键允许重新分配，照片 ID、账号归属和相册引用保持不变，所以重复恢复是幂等的。

在线补回不是“把整个网站强制回滚到昨天”。如果现有数据已变化，或数据库记录仍在但底层原文件损坏，请在全新目标进行完整恢复，核对后再计划切换，避免丢失备份之后的新内容。

## 向全新目录完整恢复（不连接线上环境）

需要 Node.js 22.13 以上（建议与 CI 一致的 Node 24）以及仓库依赖：

```sh
npm ci
node scripts/backup-tool.mjs inspect "/path/to/backup.zip"
node scripts/backup-tool.mjs restore "/path/to/backup.zip" "/path/to/NEW-empty-directory"
```

两条命令也接受备份文件夹。恢复目标必须不存在或为空；工具拒绝覆盖非空目录。先验证所有文件，再应用仓库的 SQL 迁移并恢复数据。输出为 `database.sqlite`、SQLite 日志文件（若尚未检查点）和 `objects/` 照片目录，文件索引存于数据库 `_file_objects` 表。复制运行中的 SQLite 数据库应先停止写入并关闭连接或使用 SQLite 备份功能，不能只拷贝主文件而遗漏 WAL。

此工具恢复数据，不会部署新服务器，也不会修改当前网站。将来部署 Node 服务时，仍需接入 HTTP 路由运行时、邮件服务、管理员邮箱、会话密钥及图像服务密钥，再验证 HTTPS、域名、访问控制、分享链接和备份后的增量内容。正式切换前保留原站回退路径。

## 可替换存储接口

- `lib/storage/contracts.ts`：数据库语句／事务、文件读写删除及分页列举契约。
- `lib/storage/cloudflare.ts`：目前使用的 D1／R2 适配器；现有数据键和绑定不变。
- `lib/storage/runtime.ts`：可信服务器启动时可调用 `configureStorage(adapter)` 替换实现，没有用户可控的存储目的地或管理页面任意 URL。
- `scripts/storage-local.mjs`：可运行的 SQLite＋本地文件实现，已用于完整恢复和原文件校验；文件名按对象键哈希生成，备份路径不会成为本地绝对路径。
- 新增 S3 或其他数据库实现时，必须保证 `batch` 全部提交或全部回滚、分页完整、对象字节不变，再运行契约及业务测试。

## 管理员模型配置

当前没有设置覆盖时，继续使用原服务器环境中的模型；此次发布保持 **OpenAI `gpt-image-2`、1536×1024、中等质量**，没有自动切换。

管理页允许选择已有的 OpenAI／火山方舟适配器，填写模型或接入点 ID、尺寸及质量。未配置相应服务器密钥的服务不能启用。修改必须勾选确认，再保存；保存本身不会调用模型或扣除额度。参数是非秘密数据，带版本并发保护及管理审计。后续出图读取已保存参数，历史图片、任务结果和用户额度不变。

管理页只检查格式及服务器密钥是否存在，不宣称验证了模型权限、余额、兼容性或出图质量。首次换新模型后需用授权素材实际出图验收。当前两种服务的请求地址固定；接入不同协议的平台需要增加适配器，不能仅填一个任意 URL。密钥永远通过服务器安全环境配置，不能写到浏览器或 GitHub。

## 自检

```sh
npm run typecheck
npm run test:auth
npm run test:admin
npm run test:business
npm run test:exports
npm run build:pages
```

`test:admin` 使用隔离的真实 SQLite 与文件目录，覆盖管理权限、现有模型默认值、配置并发、维护锁、完整性校验、冲突、照片暂存、提交失败回滚、重复恢复、并发取消及 ZIP→全新目录恢复。测试图像服务使用固定响应，不消耗线上额度。测试结果和临时备份位于 Git 忽略的 `outputs/`。生产验收只做真实备份下载、校验和无写入预览，不通过破坏线上数据来测试恢复。
